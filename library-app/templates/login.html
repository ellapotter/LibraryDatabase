How We Met the Deliverable 5 Requirements

Important Note

  • The buttons with a lavender background color represent the functionality that we are using to meet the deliverable 5 requirements.
  • The buttons with a blue background color represent additional functionality we added beyond what is required for deliverable 5

When Logging in as a Patron...

  • First Query: The "View Library Fees" button shows the patron's unpaid fee total using a join and an aggregate function
  • Second Query: The "View Your Room Reservations" shows the patron's upcoming reservations using a view called Patron_Reservation_View
  • A Function: The "View Library Fees" button calculates the patron's total unpaid fees using a function
  • Operation Showcasing a Trigger: A trigger is in place to automatically deny any new reservation that takes place in the same room at the same day and time as an existing reservation. To view this, the patron can attempt to create a duplicate reservation using the "Add New Reservation" button and will see that it results in an error.
  • CRUD Functionality: The patron role is able to CREATE new reservations, READ multiple tables of data, UPDATE their email address, and DELETE reservations they have created.

When Logging in as Staff

  • Third Query: The "View Patrons with Current Checkouts" button uses both a join and a subquery
  • Fourth Query: The "Search Library Book Collection" button uses a join
  • Fifth Query: The "View Total Checked Out Materials" button uses an aggregate function and a join in the query
  • A Procedure: The "Apply Late Fees" button uses a procedure to apply the late fees
  • CRUD Functionality: The staff role is able to CREATE new patron accounts, READ multiple tables of data, UPDATE late fee amounts, and DELETE patron accounts.
